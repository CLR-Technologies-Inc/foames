Notes on the 2026-11-16 runs, added to the README by publish_results.py.

- Gemini's `spc-ewma-chart` is from its third attempt (workflow run 43871563784). The first met the free tier's limit of 20 requests a day (HTTP 429) and the second got HTTP 503 (model overloaded) on every request; both are kept out of the scores, in `runs/run-aider-gemini-flash-all_/dropped-rate-limited.jsonl` and `runs/run-aider-gemini-flash-spc-ewma-chart_/dropped-unavailable.jsonl`.
- The first local-model run (workflow run 43784200629) is not in this report: on 4 CPU cores most requests outlived aider's 600-second timeout and were retried until aider gave up, so its scores measured the timeout. The local models were rerun with a one-hour request timeout.
- OpenRouter's `qwen/qwen3-coder:free` had gone paid-only; the agent ran on the free model with the largest context window that day, `thinkingmachines/inkling-2-small:free`.
- Local models on the 4-vCPU runners mostly ran out of time: each task's limit is thirteen times its budget (up to 3.25 hours), and many runs used all of it while producing a few thousand tokens. Of the 34 local models, only gpt-oss 20b passed a task (1 of 6). On CPU these scores say more about speed than about what the models can do; the GPU notebook runs the larger models without that limit.
- NVIDIA Build (NIM) agents ran on the free development credits, with each model picked from the key's live catalogue that day (`model-digest.txt` on each agent's page). The catalogue offered no Kimi or Qwen3-Coder model, so those agents were skipped. It also lacked gpt-oss 120b and Llama 3.3 or 4, so `aider-nvidia-gpt-oss-120b` ran on `openai/gpt-oss-20b` and `aider-nvidia-llama` on `meta/llama-3.2-90b-vision-instruct`. MiniMax's first run met HTTP 503 ("content safety screening is temporarily unavailable"), and the picker now retries a busy endpoint before giving up.
- The NVIDIA agents ran the six core tasks and the 29 sector case studies in one job each. GitHub's 6-hour job limit cut four of them short: DeepSeek after 8 tasks, Laguna after 12, Gemma after 13 and MiniMax after 14. The rest of Gemma's and Laguna's tasks, and the SPC task for DeepSeek and MiniMax, are rerunning in shorter jobs (workflow runs 43887911008 to 43887993586). DeepSeek's and MiniMax's remaining sector tasks are not rerun, because both hit the one-hour task limit on most sector tasks they started and passed none.
- The Claude Code agents ran the 29 sector case studies on this account's Claude subscription, not the API. They used Claude Code 2.1.325 in a Linux cloud container with the unshare sandbox, on tasks from commit c8bf84e (now on main). The cost is $0. The list-price column is Claude Code's own API-equivalent estimate for the same tokens. The subscription's 5-hour usage limit stopped the runs twice; a run cut off by the limit was thrown away and started again after the reset, so no score counts a limit message. The current four tiers ran (Haiku 5.5, Sonnet 5.5, Opus 5.5, Fable 5.2). The older Opus 5, Opus 4.8, Sonnet 4.5 and Haiku 4.5 also work through the CLI but were not run this time, to stay inside the shared usage limit. ECL reached shows none for now because ECL counts every task at a level and below, and the Claude agents have not yet run the six core tasks; those runs are under way.
