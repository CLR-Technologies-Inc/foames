# Vendor interoperability and published terms

FoaMES connects to other companies' products. This page records, for every vendor FoaMES integrates with or plans to, what that vendor discloses publicly about its interface, what its published terms say about using that disclosure, and what that means for code in this repository: what can be written here freely, what cannot, and where each item sits on the roadmap.

> **Not legal advice.** This page is an engineering summary of public statements, written by the FoaMES maintainers so that contributors make consistent choices. It is not legal advice, it is not a legal opinion on any vendor's terms, and it does not create any right to use a vendor's product. Terms change, differ by country and are overridden by whatever contract a site has signed with its vendor. Each row was read on **2026-11-16**; check the cited page again before relying on it, and ask a lawyer before you depend on any conclusion here. Where a cell says "not found" or "not read", that means only that the research did not find or could not reach the text, not that no restriction exists.

FoaMES works with these products **as an interoperability client under each vendor's published terms**. It is not affiliated with, endorsed by, sponsored by or certified by any vendor named here. Product names are used only to say what FoaMES connects to; they are trademarks of their owners (see [Trademarks](#trademarks)).

## How to read the table

Three different things are often confused when people ask whether an API "can be reproduced":

1. **The interface facts**: that an endpoint exists at a path, the names of its fields, its authentication style, a wire protocol. FoaMES needs these to interoperate, and writes its own client code around them. This is the lowest-risk layer, and it is what every shipped integration does.
2. **The vendor's expressive material**: documentation prose, tutorials, code samples, downloadable specification files (OpenAPI, EDMX, WSDL, XSD), SDK libraries and binaries. Almost every vendor below forbids copying or redistributing these without permission. FoaMES does not copy, vendor or redistribute any of it.
3. **The contract that binds a licensee**: a site that licenses the vendor's product (and sometimes anyone who reads the documentation) has agreed to terms that may forbid reverse engineering, benchmarking, "forking" the API, or using the interface with software the vendor has not authorised. These bind the person who accepted them. A FoaMES contributor who has accepted such terms is bound by them when contributing; a site running FoaMES is bound by its own licence when it points FoaMES at its system.

So each row answers: what is publicly disclosed (layer 1), what can be written here from it, what cannot (layers 2 and 3, plus anything needing a licence or partner programme), and where it is on the roadmap.

**Roadmap placement** uses: **Shipped** (on `main` today, alpha), **0.3.x** (the next minor line, once the 0.2.0 release is cut), **Later** (wanted, after 0.3.x, usually waiting on a terms question), **Out of scope** (FoaMES will not do this).

## What this means for contributors

These rules apply to every adapter, bridge, profile, test and document in this repository.

**You may**

- Write your own client code from a vendor's **publicly readable** documentation, using endpoint paths, field names, authentication styles and protocol details as the facts needed to interoperate.
- Implement open specifications (Sparkplug B, OPC UA, DEXPI, ISA-95 concepts) under their own licences.
- Keep paths that are not publicly documented out of the code, and let the site enter them in its MES Connection or adapter settings from its own licensed documentation (this is how the shared MES framework already works).
- Write small test stand-ins that return the minimum fields a client reads, written by you, not captured from a vendor system.
- Name a product to say what FoaMES connects to: "connects to SAP S/4HANA", "a client for the Tulip Tables API".

**You may not**

- Copy documentation text, tutorials, code samples, or downloadable specification files (OpenAPI, EDMX, WSDL, XSD, nodesets) into the repository unless the vendor's licence for that file allows it and its notice comes with it.
- Commit anything you could only read after signing in to a vendor portal, customer site, partner programme or licensed installation, or anything covered by a confidentiality obligation you accepted.
- Add vendor SDKs, client libraries or binaries to the repository. If an SDK is ever needed, it is installed by the site under the vendor's terms.
- Reverse engineer, decompile or capture traffic from a vendor's product to learn an interface, or work around licensing, metering or technical limits.
- Build a server, mock or emulator that reproduces a vendor's API surface for others to use as a substitute for the vendor's product. Tulip's API licence forbids this outright ("Forking"); for the others it is out of scope as a matter of policy.
- Publish benchmarks or performance comparisons of a vendor's product. Rockwell's agreement and Tulip's terms forbid it; for the others it is out of scope. The FoaMES agent benchmark measures coding agents working on FoaMES, never a vendor's product.
- Use a vendor's logo, put a vendor's name into a FoaMES product, package or company name, or claim certification, conformance, partnership or endorsement that has not been granted ("OPC UA certified", "Sparkplug Compatible", "SAP certified" all need the owner's programme).
- Point an automated agent or scraper at a site whose terms or `robots.txt` forbid it. SAP's terms name MCP and agent frameworks explicitly; Dassault Systèmes forbids robots and data mining; SAP's hubs and GE Vernova's documentation disallow automated readers. A person reads those pages.

**A site that connects FoaMES** to a vendor product does so under its own licence with that vendor. Some licences restrict which third-party software may use the vendor's interfaces (Rockwell §1.4.10) or require an access licence (AVEVA PI's PSA). FoaMES's read-only mode and its outbox keep writes under the site's control, but checking the site's own licence is the site's responsibility.

## Background: why interface facts are treated differently

Courts and legislators have generally drawn a line between an interface and the expression around it, though the line differs by jurisdiction and contracts can move it:

- In the European Union, the Software Directive (2009/24/EC, Article 6) allows decompilation only where needed for interoperability and under strict conditions, and the Court of Justice held in *SAS Institute v World Programming* (C-406/10, 2012) that a program's functionality, programming language and data file formats are not protected as expression; it also held that copying the manual's expression can infringe.
- In the United States, the Supreme Court held in *Google v. Oracle* (2021) that Google's reimplementation of the Java API declarations was fair use on those facts, without deciding whether APIs are copyrightable. US courts also enforce contractual terms (EULAs, terms of use) that restrict reverse engineering, so a licensee can give up rights the copyright law would otherwise leave them.

FoaMES does not rely on any of these cases to justify copying. It avoids the question by writing its own clients from public facts, keeping undocumented details in site configuration, and staying out of the emulation and benchmarking business. The cases are mentioned only so readers understand why the table separates "interface facts" from "material" and "contract".

## Keeping this page current

- Add a row **before** starting work on a new vendor, and cite the pages you read. Add each cited terms page to `.github/vendor-terms/pages.json` too.
- The **Vendor terms** workflow (`.github/workflows/vendor-terms.yml`) re-checks the cited pages every Monday. For pages whose sites allow automated access it respects `robots.txt`, uses a generic user agent, and compares a SHA-256 of the page's visible text with the reviewed hash in `.github/vendor-terms/state.json`; a changed, broken, unreachable or newly disallowed page opens or updates an issue labelled `vendor-terms`. Pages whose terms forbid bots (SAP, Dassault Systèmes, Critical Manufacturing's site terms), whose `robots.txt` disallows readers (SAP's API hub, GE Vernova) or that only render in a browser (AVEVA's docs, the Plex portal) are never fetched; the first Monday of each month a reminder issue lists them for a person to read. No vendor text is stored, only hashes. After reviewing, update this page and `state.json` in one pull request. The check spots changes; it does not decide whether FoaMES still complies, which stays a human (and, where needed, legal) judgement.
- When a vendor's terms change, update its row and the date at the top.
- Gaps to close (pages that could not be read on 2026-11-16): SAP Business Accelerator Hub terms and SAP digital access licensing; the Insights Hub licence page and Siemens trademark statement; Plex developer portal terms; FactoryTalk ProductionCentre public material; the 3DS trademark page; the Aegis software addendum; Körber software terms; all GE Vernova Proficy terms; the Inductive Automation SDK terms; InfluxData and Frappe website trademark pages; the DEXPI licence version; the Sparkplug TCK licence; the OPC Foundation source deliverable agreement.
